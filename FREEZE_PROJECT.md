# Freeze Project

Если сервер скоро заканчивается, а проект нужно "заморозить", сохраняй его в 4 слоях:

1. Код
2. База данных
3. Загруженные файлы и медиа
4. Серверные конфиги и секреты

## Что нужно сохранить

### 1. Код

Сохранить локально и в git:

- `admin-web/`
- `server/`
- `app/`
- корневые конфиги: `package.json`, `app.json`, `babel.config.js`, `tailwind.config.js`

### 2. База данных

Нужно отдельно снять дамп рабочей БД.

Если это Postgres:

```bash
pg_dump -Fc -h HOST -U USER DB_NAME > edumap-postgres.dump
```

Если это MySQL:

```bash
mysqldump -h HOST -u USER -p DB_NAME > edumap-mysql.sql
```

Если часть данных живет в Supabase, сохранить нужно:

- `SUPABASE_URL`
- `SUPABASE_SERVICE_ROLE_KEY`
- `NEXT_PUBLIC_SUPABASE_URL`
- `NEXT_PUBLIC_SUPABASE_ANON_KEY`
- доступ к проекту Supabase

### 3. Файлы и медиа

Нужно отдельно сохранить все, что не лежит в git:

- пользовательские загрузки
- документы
- изображения
- локальные JSON-хранилища
- экспорт новостей/контента, если он не в git

### 4. Серверная конфигурация

Нужно сохранить:

- `.env`
- nginx config
- pm2 config
- SSL-сертификаты
- домены и DNS
- IP сервера
- данные SSH

## Что известно по текущему проекту

- web API по умолчанию: `https://api.edu-map.kz/api`
- мобильный root `.env` все еще содержит старый `onrender` URL
- прод backend на VPS: `185.129.51.161`
- backend процесс на VPS: `pm2` процесс `edumap-server`
- рабочая папка backend на VPS: `/var/www/edumap/app/server`

## Рекомендованный план заморозки

1. Снять дамп БД
2. Сохранить `.env` и конфиги сервера
3. Сохранить медиа/загрузки
4. Собрать локальный архив кода
5. Проверить, что архив и дамп открываются
6. Оставить домен активным, если он нужен в будущем
7. После проверки отключить VPS

## Локальный архив

В репозитории есть скрипт:

```bash
./scripts/freeze-local.sh
```

Он собирает архив с кодом проекта и служебный `manifest`.

## Серверный чеклист

Для сервера есть шаблон-команды:

```bash
./scripts/freeze-server-template.sh
```

Этот файл не выполняет ничего сам. Это готовый список команд, которые нужно
запускать уже на VPS.
